Лабораторный анализ строковых типов и памяти в C#

Задание 1. Обработка строки s = "  Ахметов Ерлан;85 "

1. Метод .Trim() убирает лишние пробелы по краям. Получаем: "Ахметов Ерлан;85".
2. При вызове .Split(';') строка разбивается на две части:
   - Первый элемент массива: "Ахметов Ерлан" (длина составляет 13 символов).
   - Второй элемент массива: "85" (длина составляет 2 символа).

Задание 2. Проверка int.TryParse для строки "Иванов Пётр;70;85;x"

После разделения исходной строки через Split(';') сформировался массив под индексами от 0 до 3:

- Индекс 0 ("Иванов Пётр"): int.TryParse вернет false, переменная out станет 0, так как это текст.
- Индекс 1 ("70"): int.TryParse вернет true, переменная out запишет число 70.
- Индекс 2 ("85"): int.TryParse вернет true, переменная out запишет число 85.
- Индекс 3 ("x"): int.TryParse вернет false, переменная out станет 0, потому что буква не является числом.

Что насчет TryParseScores?  
Если функция проверяет числовые ячейки (индексы 1 и 2), то результат будет успешным (true). Если же под проверку попадет ФИО или символ "x", метод выдаст false, поскольку парсинг не сможет преобразовать нечисловые символы.

Задание 3. Сравнение памяти: string (+=) против StringBuilder

- Обычные строки (string):  
  При выполнении цикла s += i каждый шаг создаёт абсолютно новый объект в памяти, так как строки неизменяемы. Для 4 итераций плюс пустая строка "" в куче будет создано 5 разных строковых объектов (старые остаются до сборки мусора).

- Класс StringBuilder (sb.Append(i)):  
  Работает внутри одного выделенного буфера. При добавлении элементов объект в памяти не пересоздаётся заново для каждого шага. Всего используется 1 объект StringBuilder.

Задание 4. Поведение метода s.ToUpper() без присваивания

Строки в C# имеют свойство иммутабельности (неизменяемости). 
Метод ToUpper() не меняет текущую область памяти, а создаёт совершенно новую строку с заглавными буквами и возвращает её результат. 

Если не сохранить этот результат через присваивание (s = s.ToUpper();), исходная переменная продолжит ссылаться на старый объект, поэтому внешне строка никак не изменится.
